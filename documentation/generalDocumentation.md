## Padrões de escrita de Issues
O título da Issue deve começar com um verbo, por exemplo: Fazer, Resolver, Implementar... Descreva em poucas palavras o que é para ser feito, de forma objetiva e clara.

A descrição da Issue deve ser usada para informar o que deve ser implementado ou corrigido.

Exemplo:

### Título: Criar arquivo main.py
Descrição: Criar o arquivo main.py com os conteudos iniciais do projeto, com a função tal.

**Sempre assinem a issue, para mostrar quem será o responsável.**

<br>

## Instruções de Pull Request e Review
Nunca deverá ser feito Pull diretamente na Branch main, sempre deve ser feito as features ou fix em uma branch separada de acordo com a issue.

Assim que terminado deverá ser criado um Pull Request para fazer o merge na main, e deverá ser designado outro integrante da equipe para fazer a revisão do código e autorizar o merge.

Quem não sabe o que é e como faz o Pull Request, pesquisem.
